まず、プロジェクトに小さな機能を追加しました。より大きな変更には、より確実なプロセスが必要です。GitHub Copilot CLI は組織の既存のフローに沿って動作するため、適切なものを適切な方法で構築できます。このレッスンは、エージェントを使った一般的な開発プロセスを学ぶ一連のレッスンの最初の内容です。issue から新機能を作成し、コードの有効性と機能の動作を確認してから、プロジェクトにマージします。

> [!NOTE]
> 機能開発の一連の作業では、同じ会話とブランチを使います。通常はファイルの種類ごとに異なるブランチやプル リクエストを使いますが、ここでは主な概念に集中するために簡略化します。

このレッスンでは、次の操作を行います。

- GitHub issue から Copilot の会話を開始します。
- Plan モードで要件を定義します。
- Autopilot モードで新機能を実装します。
- コードをレビューします。
- Codespaces の転送ポートを使って、ブラウザーで機能を手動で検証します。

この機能の開発を続ける中で、リポジトリの手順を更新し、既存の `quality-checks` スキルをカスタマイズし、MCP による検証を追加して QA エージェントを作成し、機能のプル リクエストを開きます。

## シナリオ

Tailspin Toys のカタログは拡大しており、訪問者はカテゴリやパブリッシャーでゲームを絞り込む必要があります。バックログの issue には機能の概要がありますが、カテゴリを組み合わせる方法など、コーディング前に合意が必要な詳細があります。Plan モードで決定事項を整理し、Autopilot に範囲を限定した実装を許可します。

## 背景

生成 AI を開発プロセスに導入しても、ソフトウェア開発の基本は変わりません。むしろ、より重要になります。多くの開発者は次のようなプロセスに従います。

1. 作業内容を説明する issue から始めます。
2. 作成するものを計画します。
3. コードを作成してレビューします。
4. テストを実行してコードを検証します。
5. 新しい機能を手動で検証します。
6. プル リクエスト (PR) を作成します。
7. コードレビューと継続的インテグレーションのチェックが完了したら、コードをマージします。

> [!NOTE]
> 詳細はチームや組織によって異なりますが、ほとんどのプロセスは上記の流れを調整したものです。

標準的な進め方を守ることで、AI が生成したコードが要件を満たし、手書きのコードと同じレビュー プロセスを通るようにできます。

## 会話モード

**会話モード**は、エージェントにどの程度の自律性を与えるかを制御します。<kbd>Shift</kbd>+<kbd>Tab</kbd> を押すと、モードを切り替えられます。

- **Interactive**: エージェントと一緒に作業します。エージェントは変更を提案し、続行する前に入力を待ちます。
- **Plan**: エージェントが計画を作成します。プロジェクト ファイルを編集することはできません。
- **Autopilot**: エージェントが自律的に作業します。コードを作成し、テストを実行し、タスクが完了するまで反復します。

まず Plan モードで計画を確認し、その後 Autopilot で実装します。

## issue から始める

フィルター機能の作業を始める前に、Codespace に戻り、リポジトリとターミナルの準備ができていることを確認します。

1. Codespace に戻ります。停止している場合は、再起動してから続行します。
2. 星評価のプル リクエストがマージ済みであることを確認します。
3. ターミナルが開いていない場合は、<kbd>Control</kbd>+<kbd>\`</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>\`</kbd> (Windows/Linux) を押します。
4. `main` を更新し、フィルター機能用のブランチを作成します。

   ```bash
   git checkout main
   git pull --ff-only
   git checkout -b game-filters-cli
   ```

5. Copilot CLI を起動します。

   ```bash
   copilot --yolo
   ```

6. <kbd>Tab</kbd> を 2 回押して **Issues** タブを開きます。
7. <kbd>A</kbd> を押してすべての issue を表示します。
8. 方向キーで **Allow users to filter games by category and publisher** というタイトルの issue を選択します。
9. <kbd>C</kbd> を押して issue をプロンプトに追加し、**Session** タブに戻ります。

プロンプトが `#7` (または同様の番号) で始まることを確認してください。`#` を使うと、GitHub issue やプル リクエスト (PR) をコンテキストに追加できます。

## フィルター機能を計画する

計画を作成すると、Copilot に作業を依頼する前に、機能の実装方法やタスクの進め方を定義できます。複雑な作業では、時間をかけて計画することをお勧めします。Plan モードに切り替えて、Copilot に計画を作成してもらいましょう。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Plan モードに切り替えます。プロンプトの下にあるモード表示が **Plan** であることを確認します。
2. 前の手順で追加した issue の参照の後に、次のプロンプトを入力します。

   ```plaintext
   Create a plan for implementing this feature.
   ```

Copilot が計画の作成を開始します。まずプロジェクトを調査してから、最適な方法を検討します。

3. フィルターの動作について質問されることがあります。希望に基づいて回答してください。正解は 1 つではありません。
4. 計画が完成したら、<kbd>Control</kbd>+<kbd>E</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>E</kbd> (Windows/Linux) を押して展開します。
5. 計画を上下にスクロールしてレビューします。
6. 決定した内容と合わない部分があれば、Copilot に修正を依頼します。

## Autopilot を承認する

計画の作成とレビューが完了したら、実装に進みます。Autopilot を使って Copilot に作業してもらいましょう。

Autopilot を使うと、Copilot は問題が解決したと判断するまで作業を反復します。

1. **Accept plan and build on autopilot (recommended)**、またはインストール済みのバージョンで同様の名前が付いたオプションを選択します。
2. プロンプトの下にあるモード表示が **Autopilot** であることを確認します。
3. Copilot が計画に沿ってコードを生成し、テストを実行しながら反復する様子を確認します。

> [!NOTE]
> 承認すると、すぐに実装が始まることがあります。先に計画をレビューしてください。依存関係が不足している、またはポートが競合していると Copilot が報告した場合は、チェック完了とみなす前にセットアップの問題を解決してください。

## 実装をレビューして検証する

生成されたコードは、ほかのコードと同様にマージ前にレビューする必要があります。コードをレビューし、サイトを実行して問題がないことを確認しましょう。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Interactive モードに切り替えます。モード表示に **Plan** も **Autopilot** も表示されていないことを確認します。
2. `/diff` を入力して、フィルター機能の実装とテストを確認します。
3. 結果を issue および計画中に決めた内容と比較します。
4. コードのレビューが完了したら、<kbd>Esc</kbd> を押して diff ビューを終了します。
5. プロジェクトのチェック結果を確認し、失敗があれば Copilot に修正を依頼します。

## 新しい機能を確認する

コードに問題がないように見えても、実際に動くでしょうか。前と同じようにアプリを起動し、Codespaces の転送ポートからサイトを開きます。

1. Copilot にアプリの起動を依頼します。

   ```plaintext
   Start the app so I can try the filtering feature in my browser. Tell me the URL and leave the server running.
   ```

2. Codespaces でポート `4321` が利用可能になったら、**Open in Browser** を選択します。
3. カテゴリとパブリッシャーによる絞り込みや、計画中に決めた組み合わせを試します。
4. リセットと結果が空の場合の動作が、issue と決定事項に合っていることを確認します。
5. Codespace に戻り、Copilot に起動した開発サーバーを停止するよう依頼します。

- Autopilot モードで新機能を実装しました。
- コードをレビューしました。
